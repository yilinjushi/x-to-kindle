Anthropic 风控指纹特征分析调研报告

Anthropic 在 claude.ai 与 platform.claude.com 全站加载的风控脚本 s-cdn.anthropic.com/s.js

1 项目介绍

_图 1　风控全链路：浏览器采集 → Sift 服务器评分 → Anthropic 处置

s-cdn.anthropic.com/s.js 是美国反欺诈公司 Sift（原名 Sift Science）的浏览器信标（beacon，嵌在页面里、把设备与环境信息回传服务器的脚本）。Anthropic 把它挂在自己的子域名下，claude.ai 和开发者平台 platform.claude.com 的每个页面都会加载。页面路径每变化一次，它就把约 79 项设备、浏览器与页面信息拼进一个 1×1 GIF 请求发出去。这个子域名通过 DNS 别名直接指向 Sift 的服务器，证书也归 Sift 所有，所以数据名义上发给 anthropic.com，实际直接落到 Sift。Sift 据此识别设备，把设备和账户连成关联图谱，再结合它在 3.4 万个客户站点积累的数据打分；Anthropic 按分数决定放行、要求验证还是封禁。

1.1 核心结论

上报什么：每次约 79 个字段、约 1.2 KB，分五类。 身份标识：账户 UUID 明文、__ssid 设备 cookie、会话 ID 的 MD5。 硬件派生信号：显卡型号哈希、canvas 指纹、音频指纹、CPU 核数、内存、屏幕、CPU 架构。 浏览器与系统环境：UA、语言、时区、插件、存储能力。 反自动化与反伪装：webdriver、无头浏览器痕迹、篡改检测、无痕检测、广告拦截。 页面上下文：完整 URL、页面标题、来源页。 不做什么：不监听键盘、鼠标，不读输入内容和剪贴板，不用 WebRTC 探测内网 IP，不读地理位置、摄像头、麦克风，不枚举字体，不加载远程代码。也没有把 ID 写进多个存储、清掉一处再从别处回填的 evercookie 做法。 服务端能做什么： 识别设备：Sift 官方称会“用多种方法计算多个设备指纹”，再叠加 IP，按概率匹配出设备 ID。 建关联图谱：把设备、账户、IP、邮箱、支付指纹连成多对多的图谱。 引入全网信誉：借助 3.4 万个站点共享的邮箱、IP、设备指纹信誉打分，按 Anthropic 设定的阈值自动放行、加强验证、转人工或封禁。 跨客户查询：2026 年推出的 Global Profile 还能按账户、邮箱、手机号，查到其他 Sift 客户那里的关联账户、封禁和拒付记录。 有没有机器码级风控： 严格意义上没有。浏览器拿不到 MAC 地址、硬盘序列号、主板 UUID、Windows MachineGuid、TPM，s.js 也没有尝试去读。 实践上，它接近“浏览器安装级”的持久识别。同一个 Chrome 里清 cookie、换 profile、开无痕之后，79 个字段中只有 __ssid 变化，其余 74 个逐字段相同。服务端几乎必然能把你认回原设备。 什么能断开关联： 登录同一账户会立刻确定关联，任何前端操作都没用。 换了浏览器内核，只剩 16 个低熵字段相同；再换网络出口和显示环境，前端层面的关联基本就断开了，但仍可能被邮箱、手机号、支付卡和行为模式在服务端连上。 所以，“这台电脑永远能被认出”不成立；“不换账户、不换浏览器、不换网络时几乎总能被认出”成立。 两个意外发现： Chrome 151 上无痕检测已经失效。 UA 篡改检测和操作系统篡改检测有代码缺陷：检测到篡改时，字段会直接从请求里消失，不会上报 true。不过“字段缺失”本身仍可能被当作信号。

⚠️ 警告 最值得注意的隐私敞口：登录后每切换一个对话，脚本就上报一次，内容包括当前完整 URL（含对话 UUID）和页面标题（对话标题的开头部分），并和明文账户 UUID 一起直接发给 Sift。这一结论来自 claude.ai 前端代码分析；调研用的浏览器没有登录，所以没有实际抓到这类请求。

1.2 术语速查

术语

释义

Sift

美国反欺诈公司（原名 Sift Science），提供设备指纹、账户滥用与支付欺诈评分。它是 Anthropic 子处理者清单上的“Fraud and abuse detection”服务商。

信标（beacon）

嵌在页面里、把设备与环境信息回传服务器的脚本或请求。本文指 s.js 和它发出的 1×1 GIF。

浏览器指纹

不保存任何 ID，而是用浏览器暴露的软硬件特征组合来识别设备。

FingerprintJS（FPJS）

开源浏览器指纹库。s.js 内嵌了它的删减版 3.4.2。

detectIncognito

开源的无痕模式检测库。s.js 内嵌 1.6.2 版。

__ssid

Sift 脚本写在 claude.ai 域名下的 cookie，值是随机 UUID，上报字段名为 uu。

CNAME 伪装（CNAME cloaking）

把自家子域名用 DNS 别名指向第三方服务器，让第三方请求看起来像第一方请求。s-cdn.anthropic.com 指向 Sift 的 b-0.hexagon-cdn.com。

MD5

一种哈希算法。s.js 对部分字段做不加盐的 MD5；原值的可能取值少时，可以用字典反查。

canvas / WebGL / 音频指纹

分别让浏览器画一张图、读取显卡型号、离线渲染一段音频，用结果的细微差异区分设备。

webdriver / 无头浏览器（headless）

前者是浏览器被自动化程序控制时暴露的标志，后者是没有界面、在后台运行的浏览器，常用于爬虫和批量操作。

设备 ID（device ID）

Sift 服务端综合多种指纹和 IP 算出的设备标识，与 __ssid cookie 不是一回事。

Global Data Network

Sift 在 3.4 万多个客户站点之间共享的风险数据网络。

Global Profile

Sift 2026 年推出的跨客户身份查询接口。

Events API

客户（这里是 Anthropic）把注册、登录、支付等业务事件回传给 Sift 的服务端接口。

机器码

本文指硬件级的唯一标识，例如 MAC 地址、硬盘序列号、主板 UUID、Windows MachineGuid、TPM 背书密钥。

2 脚本是谁的：Sift 信标 v122 与它在 claude.ai 上的接法

2.1 一份原样使用、由 Sift 托管的第三方脚本

文件头部的注释列出了脚本打包的开源代码：crypto-js、fingerprintjs2、FingerprintJS v3、detectIncognito。脚本内部的版本号字段是 122。三处来源的比对结果如下：

  • 内容与官方原版一致：把 s-cdn.anthropic.com/s.js 与 Sift 官方地址 cdn.sift.com/s.js、cdn.siftscience.com/s.js 当天的文件比对，三份文件的 MD5 都是 4e494a08…，格式化后 diff 为空。【实测】

  • 跟随最新版：与 Sift 锁定版本的 js/s-122.js 相比只差 1 个字节（sri:&quot;0&quot;）。说明 Anthropic 加载的是“浮动最新版”，Sift 发布新版本后，claude.ai 上会自动生效。【实测】

  • 由 Sift 托管：s-cdn.anthropic.com 的 DNS 是一条 CNAME，指向 b-0.hexagon-cdn.com。TLS 证书主体是 O=Sift Science, Inc.，同一张证书还覆盖 OpenTable、Razorpay、DigitalOcean 等 Sift 客户的子域名。Anthropic 只是把子域名指了过去，脚本和数据接收都在 Sift 的服务器上。【实测】

从证书和网页存档可以排出时间线：

  • 2023-10-05：Anthropic 首次为这个子域名签发证书。此后 20 个历史版本里，有 19 个能在 Sift 官方地址的存档中找到完全相同的文件，剩下 1 个只是 gzip 编码不同。

  • 2024-12：加入 FingerprintJS 3.4.2，带来 WebGL 与音频指纹。

  • 2025-11：v118 加入无痕检测。

  • 2026-03：v120 加入 webdriver、窗口外尺寸、通知权限三项反自动化信号。

  • 2026-11-11：升到 v122。

这说明反自动化能力一直在增强，而且增强是 Sift 推送的，不是 Anthropic 自己改的。

_图 2　s.js 的构成：73% 是内嵌开源库

58 KB 里真正负责采集的不到一半：FingerprintJS 约占 28%，detectIncognito 约 15%，Sift 自有信号约 12%。其余是 crypto-js 的 MD5 实现、Babel 运行时，以及传输与命令队列。

FingerprintJS 被删掉了 7 个组件：

  • 字体枚举既最耗时、区分度也最高，被删后没有任何替代实现。

  • canvas、广告拦截、vendor 三项由 Sift 自己的信号补上。

FPJS 自己会算一个总指纹 visitorId，但它是“用到才计算”的属性，Sift 从来不读，所以既不计算也不上报。Sift 要的是原始组件，指纹在服务端自己算。【代码】

3 一次上报怎么发生

_图 4　一次上报的时序

每次调用 _trackPageview，脚本都会先浅拷贝当前配置，然后同时启动两组采集：

  • Sift 自有的 21 个信号：读写 __ssid、canvas 绘制、无痕检测、广告拦截诱饵、四项篡改检测等。

  • FingerprintJS 的 28 个组件：它会等浏览器空闲才启动，并设了 10 秒超时。

两组结果合并后改成短字段名。没有会话 ID 时，用 __ssid 的 MD5 代替。最后拼成 querystring，以 &amp;z=z 结尾，赋给一张 1×1 的 Image。请求发出后不读响应、不重试。【代码】

沙箱实测的时间线（相对页面导航开始）【实测】：

  • 48 ms：写入 __ssid。

  • 99–105 ms：绘制 canvas 并导出图像数据。

  • 128 ms：查询存储配额（无痕检测）。

  • 134 ms：离线渲染一段音频。

  • 155 ms：执行 14 次媒体查询。

  • 156–162 ms：读取 WebGL 显卡串。

  • 163 ms：发出 GIF。

整个过程不到 200 ms，用户感知不到。

结论

加密 / 签名 / 压缩

都没有。任何能看到这个 URL 的一方，包括 Sift 的服务器日志、做 TLS 解密的企业代理、浏览器扩展，都能直接读出全部内容。【实测】

哈希

cookie

3.2 频率：路径每变一次就上报一次

s.js 自己不监听任何事件，上报次数完全由页面决定。claude.ai 的规则是：

  • 路由的 pathname 每变化一次，调用一次 _trackPageview。

  • 首次加载算 1 次。

  • 切换对话（/chat/&lt;uuid&gt;）、进入设置或升级页各算 1 次。

  • 发生重定向时，两个路径各报 1 次。

  • 只改 query 或 hash、在同一个对话里发消息都不上报，也没有定时心跳。

实测中，每次切换路由后 0.1–1 秒内发出请求。【实测 + 代码】

5.1 __ssid 的一生

每次上报时，脚本都去 document.cookie 里找 __ssid：

  • 找不到、值长度小于 15、或者值是字符串 "undefined" / "null"，就用 crypto.randomUUID() 生成新值，写一个“当前年份 +4”过期的 cookie。

  • 找到了就原样复用，不续期。

cookie 属性也有讲究：

  • 写入时没设置 Secure 和 SameSite，JS 写的 cookie 本来也不能是 HttpOnly。所以页面上任何脚本都能读到它，它也会随每个发往 *.claude.ai 的请求一起发给 Anthropic 的服务器。

  • cookie 域由脚本内置的顶级域名表推算，实际效果是“取最后两段”：claude.ai 上是 .claude.ai，platform 上是 .claude.com。两边的 __ssid 不同，但实测两站上报的 canvas、插件、数学库指纹完全一样。【代码 + 实测】

5.2 没有超级 cookie

全文检索并动态挂钩（hook）存储 API 之后确认，脚本不会往 localStorage、sessionStorage、IndexedDB、Cache Storage、Service Worker、window.name 写入任何标识，也不靠 ETag 或 HSTS 这类缓存机制存 ID。detectIncognito 在 Safari 和老版 Firefox 上会建一个临时 IndexedDB 数据库，随即删除；在 Chrome 上只查询存储配额，不碰 IndexedDB。所以清掉 __ssid 就是真的清掉了，脚本不会从别处把它恢复。【代码 + 实测】

5.3 s.js 之外的第一方设备标识

claude.ai 的前端另有一个第一方 cookie anthropic-device-id。它作为请求头 anthropic-device-id 随每一次 API 调用发出，也用于 GrowthBook 实验曝光事件。activitySessionId 则通过请求头 x-activity-session-id 发给后端。【代码】

这样一来，Anthropic 后端手里同时有三样东西：

  • 自己的设备 ID；

  • Sift 信标里的会话 MD5；

  • 账户 UUID。

三者可以把 Sift 的设备结论和具体业务请求精确对齐【推断】。不过这几个 ID 都是随机值，清 cookie 就会换新。

7 有没有“机器码级”风控

❗ 重要 直接回答：

• 没有硬件序列号级别的识别，网页也做不到。

• 有“浏览器安装级”的持久识别：不换浏览器内核、不换显示和系统环境时，清 cookie、换 profile、开无痕都只会换掉一个随机 ID，指纹原样保留。

• 账户、IP 和 Sift 全网数据会把剩下的缝隙补上。 “只要在这台电脑上就永远能被认出”这个说法过强，“在这台电脑的这个浏览器里，几乎总能被认出”是准确的。

_图 8　识别阶梯：从账户到硬件序列号

7.1 严格意义：浏览器拿不到硬件序列号

浏览器把网页关在沙箱里：

  • W3C 的设计原则要求，暴露给网页的设备标识应当随机生成、按站点隔离、在用户清除数据时一并清除。

  • WebRTC 早已用临时 mDNS 名替代真实的内网 IP。

  • deviceMemory 只给出取整后的档位。

  • WebUSB、WebAuthn 这类能碰到硬件的 API 都要用户逐次授权，s.js 也一个都没调用。

所以 MAC 地址、硬盘序列号、主板 UUID、Windows MachineGuid、TPM 背书密钥，网页脚本都拿不到。Sift 隐私声明的采集清单里出现过 MAC 地址，但那份清单同时覆盖 App SDK，网页端不可能拿到。【官方 + 推断】

7.2 实践意义：硬件派生信号几乎等于“这台机器的这个浏览器”

拿不到序列号，不等于认不出机器。s.js 采集的显卡型号、canvas 渲染结果、CPU 核数、内存档位、屏幕分辨率、CPU 架构、时区，都由硬件和操作系统决定，你清多少次浏览器数据都不会变。第 6 章的实验表明，在同一个 Chrome 里，它们就是一个稳定的设备签名。

Sift 官方说法与此吻合：

  • 会“用多种方法计算多个设备指纹”，指纹里还包括 IP 和屏幕尺寸。

  • 多信号指纹“按概率匹配设备”，“用户清除浏览器数据后仍能持续”。【官方】

_图 9　还能被认出来吗：断联决策树

7.3 “永远”为什么不成立

指纹会漂移： 浏览器大版本升级会改变音频、数学库和显卡串的格式； 换显示器、改缩放、驱动升级、笔记本切换独显，都会改动部分字段； 学术研究 FP-STALKER 测得，真实设备的指纹平均可被追踪 51.8 天，45.5% 的指纹一天内至少变化一项。 开源版指纹本身不精确：FingerprintJS 官方自述，开源版的准确率只有 40–60%，ID 往往只能维持几周。真实流量中只有 33.6% 的浏览器指纹是唯一的，移动端只有 18.5%；同型号新机器会撞指纹，Sift 帮助中心也承认这一点。 真正把漂移补上的是另外三样东西：登录同一账户、相同的出口 IP 或 ASN，以及 Sift 服务端的概率匹配和全网历史。这三样都不是“机器码”，换账户、换网络就能削弱。

8.1 设备解析与关联图谱

Sift 的数据模型是：一个会话对应一个设备指纹，一个设备可以对应多个用户，一个用户也可以对应多个设备。在这个模型上：

  • 页面用 _setUserId 把会话挂到账户上。

  • 登录前的匿名浏览，通过会话 ID 回溯到同一账户。

  • Console 的 Network 视图按设备 ID、cookie 指纹、IP、账单或收货地址，把共用这些属性的账户列在一起，可以批量处置。

  • 官方帮助文档直说，同一设备上有多个用户，本身就是“更强的欺诈信号”。【官方】

Device Fingerprinting API 对每台设备给出以下信息【官方】：

  • 首次出现时间；

  • 这台设备上出现过的用户列表；

  • Anthropic 自己打的 bad / not_bad 标签；

  • network.first_seen 和 network.score：前者是 Sift 在全部客户中首次见到这台设备的时间，后者是其他客户打的标签算出来的 0–1 风险分。

Anthropic 即使没有购买这个 API，Sift 的评分模型也照样使用设备指纹。【官方】

8.2 全网信誉与 Global Profile

Sift 自称每年处理 1 万亿以上事件，覆盖 3.4 万多个站点和 App。它明确写道：在网络中共享的数据包括“邮箱地址、IP 地址和设备指纹”。全局模型使用“所有客户的数据”，在一个站点识别出的欺诈者会影响其他站点的判断。

2026 年推出的 Global Profile 更进一步，可以按账户 ID、邮箱或手机号查询：

  • 这个身份在其他 Sift 客户那里有多少关联账户，分布在哪些行业；

  • 被其他客户 block 或 watch 过多少次；

  • 有过多少拒付；

  • 默认回看 12 个月。【官方】

同时，Sift 也强调“我们不给人打分，只给某站点上的某次交互打分”，阈值和处置由客户自己决定。【官方】

11 评价：边界、缺陷与隐私影响

11.1 设计上克制的地方

  • 不采集行为：没有键盘、鼠标、滚动、剪贴板、表单监听。按键节奏、鼠标轨迹这类行为生物特征都没有采。

  • Anthropic 在 HIPAA 组织、一次性凭据 URL、福利页、桌面端授权页等场景下不加载 Sift，并对 q、returnTo 两个参数脱敏。

配额判据过时，普通窗口和无痕窗口一样

tm、db 是死字段

time_ 从来没有被赋值；1 == openDatabase 恒为 false

屏幕字段的排序 bug

FPJS 对宽高做字典序排序，1366×768 被报成 768/1366

cookie 域推算

遇到 .co.uk、.com.cn 这类多级后缀会算错，导致每次都重新生成 ID。claude.ai 不受影响

URL 脱敏不完整

只处理 query 里的指定参数，路径和 #hash 原样上报；实测带出过 Cloudflare 人机挑战的一次性 token

11.3 隐私影响与你的权利

数据直达第三方：数据名义上发给 anthropic.com 的子域名，实际进入 Sift 的服务器，浏览器的第三方请求拦截很难识别出来。Sift 服务条款写明客户数据会与其他客户的数据“混合”（commingled），用于改进它的全局模型；隐私声明则说会在全部客户网络中关联共同的数据属性。 对话元数据外泄到第三方：登录后，对话 UUID、对话标题开头、账户 UUID 会随每次路由切换一起发给 Sift。 政策披露是笼统的： Anthropic 隐私政策只写了会把设备与连接信息（含“概率性标识符”）分享给反欺诈服务商，没有点名 Sift，也没写保留期。 Cookie 表把 __ssid 列为第一方的必要 cookie，没说明它属于 Sift。 Usage Policy 在 2026-11-12 版新增：禁止以规避检测为目的创建多个账户，禁止通过消费级订阅转售或代理。 你能做什么： 欧盟、英国、瑞士居民可以把 Sift 当作数据控制者（controller），通过 privacy@sift.com (mailto:privacy@sift.com) 或 sift.com/data-request 申请访问或删除数据，但 Sift 保留以“维护模型准确性”为由继续保存数据的权利。 美国居民按 Sift 的说法应先联系 Anthropic。

12.3 未验证事项

  • 登录状态下 ui 是否就是账户 UUID，对话页的 u、t 是否带对话 UUID 和标题：目前只有代码证据，调研用的浏览器没有登录。

  • Sift 设备 ID 的具体匹配算法、返回给不同客户的设备 ID 是否相同：官方没有公开。

  • Anthropic 启用了哪些 Sift 产品、回传了哪些 Events API 字段（尤其是支付卡和电话）、阈值怎么设。

  • 真实 GPU 机器上 fvch 的区分度，以及 Safari 下的行为：本次只测了一台无 GPU 的 Linux 机器。

  • Claude Code 设置 DISABLE_TELEMETRY 后，API 请求的 metadata 里是否仍然带 device_id：只有静态代码推断，没有抓包。

  • 社区关于“同一设备多号连坐”的说法：有正反两方面的个案，无法核实。官方材料里没有任何一处写到设备连坐。
